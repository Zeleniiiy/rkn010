# Открытые решения перед полной боевой миграцией

Код и dry-run готовы с текущими правилами, но перед полной записью на PROD необходимо подтвердить:

1. Источник недостающих реквизитов субъектов. Часть карточек `organizations`, включая тестовую карточку ПАО «Ростелеком», не содержит ИНН, ОПФ, юридический/фактический адрес, телефон и email. По согласованному правилу это не блокирует миграцию: доступные сведения переносятся, отсутствующие остаются незаполненными и попадают в журнал предупреждений.
2. В финальном Excel не представлены `code`, `lic_date_start` и `service_name`. Новые записи создаются с `lic_num` и `lic_date_end`; существующие дополнительные поля сохраняются при совпадении номера.
3. Для лицензий `152769`, `138241` и `163754` отсутствует дата окончания и нет другой строки с тем же номером, из которой её можно восстановить. Соответствующие группы намеренно пропускаются и фиксируются в журнале.
4. Нужно ли переносить процессные метаданные ручных реестровых записей (`xsd`, `titles`, `registryParams`). Их идентификаторы могут различаться между стендами; `appealEntryId` у миграционных записей отсутствует по определению.
5. Числовой порядок истории по регистрационному номеру; dry-run показывает его для ручной сверки.
