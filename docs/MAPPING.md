# Маппинг RKN010 v1

## Ключи

| Назначение | Значение |
|---|---|
| Лицензия | `ОГРН + зона нумерации` |
| Номер лицензии | зона нумерации |
| Реестровая запись | `licenseId + регистрационный номер + зона` |
| История | регистрационный номер по возрастанию как число |

`row_uuid` и «Идентификатор записи» сохраняются только в плане и журнале. Они не назначаются `_id` новых карточек.

## Excel → `forRegistry`

| Excel | RKN010 |
|---|---|

| Полное наименование | `org_name` |
| Сокращённое наименование | `short_org_name` |

| N1 | `licenceNumber1` |

| N3 | `licenceNumber3` |

Повторы N1/N2/N3 в общем поле сохраняются. Пустые номера не добавляют лишних пробелов.

## Статусы

Для каждой лицензии формируется ровно одна последняя запись `active`. Все предыдущие — `reissued`. Приказ об исключении в последней строке даёт:

- лицензия: `annulled` + `dateAnnulled`;
- последняя реестровая запись: `active`;
- вложенный `record.license.status`: `annulled`.

## Субъект

Поиск выполняется в `organizations` по ОГРН. Готовый `subject` копируется; обычная карточка помещается в `subject.data.organization` и дополняется оболочкой юридического лица `ulApplicant`.

Перед live-запуском проверяются ОГРН, наименование, тип участника, подтип юридического лица и заголовок. Точный финальный перечень заказчика добавляется в `validate_subject` после подтверждения.

## Не входит в v1

- загрузка приказов и экспертных заключений;
- создание ссылок на отсутствующие файлы;
- сроки действия лицензий.

Существующие файловые метаданные при обновлении не удаляются. Будущий блок сроков действия выключен через `ENABLE_LICENSE_VALIDITY_DATES`.
