# Маппинг RKN010 v1

## Ключи

| Назначение | Значение |
|---|---|
| Лицензия | `ОГРН + зона нумерации` |
| Номер лицензии | зона нумерации |
| Реестровая запись | `licenseId + регистрационный номер + зона` |
| История | регистрационный номер по возрастанию как число |

`row_uuid` и «Идентификатор записи» сохраняются только в плане и журнале. Они не назначаются `_id` новых карточек.

## Статусы

Для каждой лицензии формируется ровно одна последняя запись `active`. Все предыдущие — `reissued`. Приказ об исключении в последней строке даёт:

- лицензия: `annulled` + `dateAnnulled`;
- последняя реестровая запись: `active`;
- вложенный `record.license.status`: `annulled`.

## Субъект

Поиск выполняется в `organizations` по ОГРН. Готовый `subject` копируется; обычная карточка нормализуется в оболочку `ulApplicant` (13-значный ОГРН) или `ipApplicant` (15-значный ОГРНИП).

Для юридического лица скрипт пытается заполнить:

- `data.organization`: `ogrn`, `organizationalForm`, `name`, `shortName`, `inn`, `registrationAddress`;
- `xsdData`: `phone`, `email`, `factAddress`;
- оболочка субъекта: тип участника, `ulApplicant` и заголовок.

Для индивидуального предпринимателя скрипт пытается заполнить:

- `data.person`: `ogrn`, `lastName`, `firstName`, `middleName`, `inn`;
- `xsdData`: `nameIP`, `birthPlace`;
- оболочка субъекта: тип участника, `ipApplicant` и заголовок.

Поля не выводятся из наименования и не подменяются вымышленными значениями. Если выбранная карточка `organizations` не содержит части атрибутов, лицензия и реестровые записи всё равно создаются. Перечень незаполненных полей записывается как предупреждение в `migration.log` и событие `subject_incomplete` в `events.jsonl`.

Если по одному ОГРН найдено несколько карточек, выбирается карточка с совпадающим наименованием и наибольшим количеством заполненных реквизитов субъекта. Выбранный ID и IDs остальных кандидатов фиксируются событием `organization_duplicate_selected`. Если карточка по ОГРН не найдена или из неё нельзя собрать субъект с правильным ОГРН/типом, ошибка записывается для этой группы, а обработка файла продолжается.

## Не входит в v1

- загрузка приказов и экспертных заключений;
- создание ссылок на отсутствующие файлы;
- сроки действия лицензий.

Существующие файловые метаданные при обновлении не удаляются. Будущий блок сроков действия выключен через `ENABLE_LICENSE_VALIDITY_DATES`.
